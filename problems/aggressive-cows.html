Aggressive Cows

Aggressive Cows

You have k cows and stalls on a straight barn line. Put one cow per stall. Make the closest pair of cows as far apart as possible — that closest-pair distance is your answer.

⏱ ~30 min to understand

Problem Statement

Imagine stalls as numbered spots on a straight road (positions like 1, 2, 4, 8, 9). You must place exactly k cows, one cow per stall, on some of those spots.
In one sentence
Among all ways to place k cows, pick the way where the two cows that are closest together are still as far apart as possible. Return that distance.
Rules (only two):
  • Each stall holds at most one cow.
  • You must place exactly k cows (not fewer).
Stalls can be given in any order in the input — you may sort them mentally as positions on a line.
What “minimum distance” means (this confuses many people)
Place 3 cows at positions 1, 4, 8.
Gaps between neighbors: |4−1| = 3, |8−4| = 4.
The smallest gap is 3 → score for this placement = 3.

Another placement: cows at 1, 2, 9 → gaps 1 and 7 → smallest gap = 1 (worse).
We want the placement with the largest smallest gap.
Example 1 — walk through
Input: stalls = [1, 2, 4, 8, 9], k = 3
Output: 3
Best choice: cows at 1, 4, 8.
Distances: 4−1 = 3, 8−4 = 4. Closest pair is 3 units apart → answer is 3.
You cannot make the closest pair 4 apart (you only fit 2 cows with gap ≥ 4).
Example 2
Input: stalls = [10, 1, 2, 7, 5], k = 3
Output: 4
On a line: 1 — 2 — 5 — 7 — 10. Best: cows at 1, 5, 10 → gaps 4 and 5 → closest pair distance = 4.
Example 3 (why answer can be small)
Input: stalls = [2, 12, 11, 3, 26, 7], k = 5
Output: 1
6 stalls but 5 cows — almost every stall gets a cow, so some neighbors are only 1 apart. The best you can do is closest-pair distance 1.

If the wording still feels heavy, open the Explanation tab — picture guide first, then the full lecture walkthrough (stalls 0,3,4,7,9,10, k=4 → answer 3).

Constraints

2 ≤ stalls.length ≤ 10⁶
0 ≤ stalls[i] ≤ 10⁸
2 ≤ k ≤ stalls.length
All stall positions are unique
Expected complexity
Time: O(n log n + n log W)
Space: O(1) extra (after sort)
W = max position − min position (answer range)
Pattern
Binary search on answer + greedy feasibility (can we place k cows with min gap ≥ d?).

How to read the solution (4 parts)

The code does not try every placement of cows (that would be impossibly slow). It uses a standard trick:
  1. Sort stall positions so the barn line goes left → right.
  2. Guess an answer: “What if every pair of cows must be at least d apart?”
  3. Check the guess with a fast greedy pass: “Can I actually place k cows with gap ≥ d?”
  4. Binary search on d: if the guess works, try a bigger d; if not, try smaller — until you find the largest d that works.
Why this works: If gap 5 is possible, then gap 4, 3, 2… are also possible (easier). So answers are “impossible, impossible, possible, possible…” — binary search finds the boundary.
Full code — binary search on distance
O(n log n + n log W)O(1)
from typing import List

def aggressiveCows(stalls: List[int], k: int) -> int:
    stalls = sorted(stalls)
    n = len(stalls)

    def can_place(dist: int) -> bool:
        # Greedy: always put next cow at earliest valid stall
        count, last = 1, stalls[0]
        for i in range(1, n):
            if stalls[i] - last >= dist:
                count += 1
                last = stalls[i]
                if count >= k:
                    return True
        return count >= k

    lo, hi = 1, stalls[-1] - stalls[0]
    ans = 0
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if can_place(mid):
            ans = mid
            lo = mid + 1   # feasible → try larger distance
        else:
            hi = mid - 1   # too tight → shrink
    return ans

What are we binary searching?

  • We are NOT searching a stall.
  • We are NOT searching a cow.
  • We are searching a DISTANCE (the answer number d).

Each guess asks: “If every pair of cows must be at least d apart, can I still place k cows?” That question is yes/no — perfect for binary search on the answer.

Complete lecture walkthrough

Aggressive Cows is the first problem in the pattern “minimum of maximum” / “maximum of minimum” — after plain “find min” or “find max” on the answer. Below follows the classic teaching flow: understand placements → linear check → binary search.

Problem statement (tutorial example)

You get n stalls at coordinates on a line (input order may be random). You must place exactly k cows, one cow per stall (each stall used at most once).
Tutorial stalls (unsorted input)
Raw: 0, 3, 4, 7, 10, 9
Sorted on the line: 0 — 3 — 4 — 7 — 9 — 10
k = 4 cows (exactly four, not fewer)
Goal (read carefully): Among all valid ways to place 4 cows, look at the minimum distance between any two cows in that placement. You want that number to be as large as possible.

In words: maximize the minimum distance. Return that minimum distance (not the stall list).

What is “minimum distance between any two cows”?

Pick one placement. Measure distances between pairs (C1–C3, C2–C4, …). Take the smallest of those — that is the score for this placement.
Placement A
Cows at stalls: 0, 3, 4, 7
Gaps left → right: 3, 1, 3
Closest pair sits at stalls 3 & 4 (only 1 apart). That 1 is the score.
min = 1
Placement B
Cows at stalls: 0, 4, 9, 10
Gaps left → right: 4, 5, 1
Again the tightest neighbors are 9 & 10 — score stays 1.
min = 1
Placement C
Cows at stalls: 0, 4, 7, 10
Gaps left → right: 4, 3, 3
No pair closer than 3. This is the best valid placement — answer = 3.
min = 3 ★
You prefer placement C because its minimum (3) is bigger. The answer for this instance is 3.
Invalid idea: Only two cows at 0 and 10 (gap 10) — you must place all k cows. The score is always computed after placing exactly k cows.

Insight 1 — Only consecutive cows matter for the minimum

After sorting stalls, cows sit in order on the line. The closest pair is always between two cows on neighboring stalls they occupy — you do not need non-adjacent pairs to find the minimum.

That is why we sort first: then we can walk left → right and only look at consecutive placed cows.

Insight 2 — Checking “can we keep minimum distance ≥ d?”

Instead of trying every placement, ask one question for a guessed number d:
If every pair must be at least d apart, can I still place k cows?
Greedy rule (always optimal for the check):
1. Put first cow at the leftmost stall (index 0).
2. Scan stalls to the right; place the next cow at the earliest stall with stall[i] − last ≥ d.
3. Stop when you placed k cows (return true) or run out of stalls (return false).

We only care yes/no, not which exact stalls — but the greedy left-to-right placement is the right way to test.

Why earliest valid stall? (classic proof)

If you skip a stall that was already far enough from the last cow, every later cow can only move right — you have less room, never more. Placing at the earliest valid stall keeps maximum space for the remaining cows. So if any placement works at distance d, this greedy one works too.

Binary search on answer — LAST TRUE

Predicate: can_place(d) is false for large d and true for small d (monotonic). We want the last distance that is still true.

Linear search on d (brute force the answer)

Try d = 1, 2, 3, … up to max − min (here 10 − 0 = 10). For each d, run can_place(d). Last d that still works is the answer.
Try d 4 cows with gap ≥ d? Typical greedy placement
1Yes0, 3, 4, 7 (many choices)
2Yes0, 4, 7, 9 — min gap still ≥ 2
3Yes0, 4, 7, 10 — min gap 3
4NoOnly 3 cows fit (e.g. 0, 4, 7)
Why not test d = 5, 6, …? If 4 cows cannot fit with gap 4, they cannot fit with gap 5 either (stricter rule). Answers look like: ✓ ✓ ✓ ✗ ✗ ✗ …
Time: O((max−min) × n) — too slow for large coordinates → use binary search on d.

can_place — pseudocode

can_place(stalls_sorted, min_dist, k):
    count = 1
    last = stalls_sorted[0]   # first cow at leftmost stall
    for i from 1 to n−1:
        if stalls_sorted[i] − last >= min_dist:
            count++
            last = stalls_sorted[i]
            if count >= k: return true   # early exit
    return count >= k

last tracks where the previous cow sits — distance is always measured from the last placed cow, not from the first cow.

Binary search on d (optimize linear scan)

Search range: lo = 1, hi = stalls[n−1] − stalls[0] (or 1 … 10⁹ on some platforms). While lo ≤ hi, pick mid, call can_place(mid):
  • If possible → record answer, search right for a bigger d (lo = mid + 1).
  • If not possible → search left (hi = mid − 1).
Tutorial trace on [0,3,4,7,9,10], k=4:
mid=5 → no  |  mid=2 → yes, ans=2, lo=3  |  mid=3 → yes, ans=3, lo=4  |  mid=4 → no, hi=3 → stop → answer 3

Polarity trick (no extra ans variable): Keep lo in the “possible” zone and hi in the “impossible” zone. When the loop ends, hi is the maximum feasible d. (Our Solution tab uses an ans variable — same answer.)

Full solution outline + complexity (broken down)

Sorting stalls: O(n log n)
One-time — line up coordinates left → right.
Binary search on d: O(log W) guesses
W = max stall − min stall (search range for distance).
Each can_place(d): O(n)
Single left → right scan; early exit when k cows placed.
Total time: O(n log n) + O(log W) × O(n) = O(n log n + n log W)
Extra space: O(1) besides sorting input

Optional: tighten lo to the minimum gap between consecutive stalls after sort — same logic, slightly smaller range. Not required for interviews.

Common mistakes

Mistake 1 — BS on stall index

Wrong: binary search which stall to put a cow on.
Right: binary search the distance d (the answer), then greedy-check feasibility.

Mistake 2 — checking all pairs

Wrong: compare every pair of cows to validate a placement.
Right: after sorting, only consecutive cows matter for the minimum; greedy scan is enough.

Mistake 3 — distance > d

Wrong: require gap strictly greater than d.
Right: use distance ≥ d (code: stalls[i] - last >= dist).
